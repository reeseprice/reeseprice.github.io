Key concepts to know cold
Data
Mean vs Median
Mean = sum/count. Median = middle value. When data is skewed (outliers pull the mean), median is more representative. Palantir deals with messy real-world data — know which to use and why.
Data
Distribution
How values are spread across a dataset. Normal = bell curve. Skewed = tail on one side. Uniform = flat. Understanding shape tells you what analysis methods are appropriate.
Data
Cardinality
The number of unique values in a column. High cardinality = many unique values (like user IDs). Low cardinality = few (like status: active/inactive). Affects how you aggregate and index data.
Data
Null / Missing Values
Missing data isn't zero — it's unknown. Nulls must be handled explicitly: drop, fill with mean/median, or flag. Never assume null = 0 without business justification.
Data
Outlier
A value far from others. Can be errors (data quality issue) or genuine signals. Use IQR method: outlier if < Q1 − 1.5×IQR or > Q3 + 1.5×IQR.
Data
Variance & Std Dev
Variance = average squared distance from mean. Std dev = √variance. Low std dev = values cluster near mean. High = spread out. Use std dev to describe spread in plain language.
Self-check quiz
A dataset of 10 salaries has one value of $5M. Should you report the mean or median to describe a typical salary? Why? ▾
Report the median. The $5M outlier pulls the mean up dramatically, making it unrepresentative of what a "typical" person earns. The median is resistant to outliers. In real Palantir scenarios, you'd flag the outlier and explain both values.
What does high cardinality in a "customer_id" column tell you about how to aggregate it? ▾
High cardinality means many unique values — you wouldn't group by customer_id to get meaningful counts (every group has ~1 row). Instead you'd COUNT(DISTINCT customer_id) or group by a lower-cardinality field like region or product category. Cardinality shapes your aggregation strategy.
What's the difference between discrete and continuous data? Give one example of each. ▾
Discrete: countable, finite values. Example: number of support tickets (you can't have 3.7 tickets). Continuous: can take any value in a range. Example: response time in milliseconds (can be 102.47ms). This distinction affects which charts and statistical tests you use.

Core pandas patterns
import pandas as pd

# Load data
df = pd.read_csv('data.csv')

# Inspect
df.head()          # first 5 rows
df.info()          # column types + null counts
df.describe()      # mean, std, min, max per column
df.shape           # (rows, columns)

# Select & filter
df['age']                        # single column (Series)
df[['age', 'salary']]            # multiple columns
df[df['age'] > 30]               # filter rows
df[(df['age'] > 30) & (df['dept'] == 'Eng')]

# Handle nulls
df.isnull().sum()              # count nulls per column
df.dropna(subset=['salary'])    # drop rows with null salary
df['age'].fillna(df['age'].median(), inplace=True)

# Sort & group
df.sort_values('salary', ascending=False)
df.groupby('dept')['salary'].mean()

# Add a computed column
df['salary_k'] = df['salary'] / 1000
df['senior'] = df['age'].apply(lambda x: x > 40)
Self-check quiz
What does df.groupby('region')['sales'].sum() return, and what does it tell you? ▾
It returns a Series where each index value is a unique region and the value is the total sales for that region. It tells you the aggregate sales contribution per region — useful for comparing performance geographically.
What's the difference between df.dropna() and df.fillna()? When would you use each? ▾
dropna() removes rows (or columns) with any null values — use when nulls are rare and rows are expendable. fillna() replaces nulls with a value (mean, median, 0, 'Unknown') — use when you need to retain all rows. Filling with median is common for numeric columns to avoid bias from outliers.
Write a one-liner to filter a DataFrame to rows where 'status' is 'active' AND 'score' is above 80. ▾
df[(df['status'] == 'active') & (df['score'] > 80)]

Note the parentheses around each condition — required in pandas because of operator precedence. Using and instead of & will raise an error.

Key SQL patterns
-- Basic aggregation
SELECT dept, AVG(salary) AS avg_salary, COUNT(*) AS headcount
FROM employees
WHERE status = 'active'
GROUP BY dept
HAVING COUNT(*) > 5
ORDER BY avg_salary DESC;

-- INNER JOIN (only matching rows in both tables)
SELECT o.order_id, c.name, o.total
FROM orders o
INNER JOIN customers c ON o.customer_id = c.id;

-- LEFT JOIN (all rows from left, nulls where no match)
SELECT c.name, COUNT(o.order_id) AS order_count
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
GROUP BY c.name;
-- Customers with 0 orders will appear with order_count = 0

-- Business question → query pattern
-- Q: "What % of customers placed more than one order?"
SELECT
  COUNT(CASE WHEN order_count > 1 THEN 1 END) * 100.0 / COUNT(*)
FROM (
  SELECT customer_id, COUNT(*) AS order_count
  FROM orders GROUP BY customer_id
) sub;
Joins cheat sheet
SQL
INNER JOIN
Returns only rows where the join key exists in BOTH tables. Unmatched rows are excluded from both sides. Most common join.
SQL
LEFT JOIN
Returns ALL rows from the left table, plus matching rows from the right. Right-side columns are NULL where there's no match. Use to find customers with no orders.
SQL
GROUP BY vs WHERE
WHERE filters before aggregation (on individual rows). HAVING filters after aggregation (on groups). You can't use aggregate functions in WHERE — use HAVING.
SQL
COUNT(*) vs COUNT(col)
COUNT(*) counts all rows including nulls. COUNT(col) counts only non-null values in that column. Use COUNT(DISTINCT col) for unique value counts.
Self-check quiz
What's the difference between WHERE and HAVING? Why can't you use WHERE to filter on SUM(sales)? ▾
WHERE filters individual rows before grouping. HAVING filters groups after aggregation. You can't use WHERE SUM(sales) > 1000 because SUM doesn't exist at the row level — it only exists after GROUP BY runs. Use HAVING SUM(sales) > 1000 instead.
You have a customers table and an orders table. Write a query to find all customers who have NEVER placed an order. ▾
SELECT c.name FROM customers c LEFT JOIN orders o ON c.id = o.customer_id WHERE o.order_id IS NULL;

A LEFT JOIN returns all customers. Where there's no matching order, order columns are NULL. Filtering for WHERE o.order_id IS NULL isolates customers with zero orders.
Translate this business question to SQL: "Show me the top 5 products by total revenue this month." ▾
SELECT product_name, SUM(revenue) AS total_revenue FROM sales WHERE order_date >= DATE_TRUNC('month', CURRENT_DATE) GROUP BY product_name ORDER BY total_revenue DESC LIMIT 5;

The pattern: aggregate → group → filter on aggregate (if needed) → sort → limit. Practicing this translation from English to SQL is the core analyst skill.

OOP in Python — patterns to know
# Class definition
class DataPipeline:
    """Processes and transforms a dataset."""

    def __init__(self, source: str, target: str):
        self.source = source
        self.target = target
        self._records = []         # _private by convention

    def load(self) -> None:
        """Load data from source."""
        # Single responsibility: only loads
        self._records = self._read_source()

    def transform(self, fn) -> None:
        """Apply a transform function to all records."""
        self._records = [fn(r) for r in self._records]

    def record_count(self) -> int:
        return len(self._records)

# Inheritance
class FilteredPipeline(DataPipeline):
    def __init__(self, source, target, predicate):
        super().__init__(source, target)
        self.predicate = predicate  # extends parent

    def filter(self) -> None:
        self._records = [r for r in self._records if self.predicate(r)]
Key principles
Python
Single Responsibility
A class or function should do one thing and do it well. If you're writing "and" in a function description — split it. load_and_transform() → load() + transform().
Python
Encapsulation
Bundle data and the methods that operate on it inside a class. Protect internals with _ prefix. External code uses the public interface, not the internals directly.
Python
DRY Principle
Don't Repeat Yourself. If you write the same logic twice, abstract it into a function or class. Repetition = future bugs when you update one copy but forget another.
Python
Naming Conventions
Classes: PascalCase. Functions/variables: snake_case. Constants: UPPER_CASE. Be descriptive: calculate_average_salary() beats calc_avg(). Code is read 10× more than it's written.
Self-check quiz
What's the difference between a class and an instance? Give a concrete example. ▾
A class is a blueprint — it defines structure and behavior. An instance is a specific object created from that blueprint. Example: DataPipeline is the class. pipeline = DataPipeline('s3://raw', 's3://clean') creates an instance. Multiple instances can exist with different data independently.
Explain inheritance to a non-technical person in 2 sentences. ▾
Inheritance lets a new class automatically get all the abilities of an existing class, so you don't have to rewrite them. Then you can add new abilities or change specific behaviors on top of what you inherited — like a specialist who knows everything a generalist knows, plus more.
Why is the single responsibility principle important in a team codebase? ▾
When each function or class does one thing, it's easier to test (test the one thing it does), easier to debug (failure points are isolated), and easier for teammates to understand without reading the whole system. A 200-line function that loads, transforms, validates, and writes data is a maintenance nightmare — any change risks breaking all four behaviors.

Chart type guide
Viz
Bar Chart
Compare quantities across categories. Use when comparing a metric (sales, count) across discrete groups (regions, products). Horizontal bars work better with long category names.
Viz
Line Chart
Show change over time. X-axis should be time (or ordered sequence). Ideal for trends: revenue by month, daily active users. Don't use for categorical comparisons.
Viz
Histogram
Show distribution of a single continuous variable. Reveals skew, outliers, and shape. Not the same as a bar chart — bars represent ranges (bins), not categories.
Viz
Scatter Plot
Show relationship between two continuous variables. Reveals correlation, clusters, and outliers. Add a regression line to show trend direction. Correlation ≠ causation.
Mini-project: end-to-end analysis template
# ── SECTION 1: Load & Inspect ──────────────────────
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

df = pd.read_csv('your_dataset.csv')
print(df.info())
print(df.describe())
print(df.isnull().sum())

# ── SECTION 2: Clean ───────────────────────────────
df = df.dropna(subset=['key_column'])
df['numeric_col'].fillna(df['numeric_col'].median(), inplace=True)

# ── SECTION 3: Analyze ─────────────────────────────
summary = df.groupby('category')['value'].agg(['mean', 'sum', 'count'])
top_5 = df.nlargest(5, 'value')

# ── SECTION 4: Visualize ───────────────────────────
fig, axes = plt.subplots(1, 2, figsize=(12, 5))

# Bar chart: category comparison
summary['mean'].plot(kind='bar', ax=axes[0], title='Avg Value by Category')
axes[0].set_ylabel('Mean Value')

# Histogram: distribution
df['value'].hist(bins=30, ax=axes[1])
axes[1].set_title('Distribution of Value')

plt.tight_layout()
plt.savefig('analysis.png', dpi=150)

# ── SECTION 5: Summary (write this in markdown) ────
# Key finding 1: ...
# Key finding 2: ...
# Recommendation: ...

You see a bar chart where one category is 10× higher than all others. What do you do? ▾
Don't immediately report it as a finding — investigate first. Ask: is this a data error (duplicate records, incorrect join)? Is it a legitimate outlier (one massive client)? Check the raw data for that category. Verify the aggregation logic. If it's real, explain it in context: "Category X accounts for 71% of revenue — this is driven by Client Y, which signed a $5M contract in Q3." Always show you validated the data before drawing conclusions.
Why would you use a class instead of a standalone function for a data pipeline? ▾
A class lets you bundle state (the data being processed, config settings, error log) with the behavior (load, transform, validate, write) that operates on it. With standalone functions, you'd pass state around as arguments constantly. A class also enables inheritance — a FilteredPipeline can extend a base DataPipeline without rewriting the shared logic. For a one-off script a function is fine; for a reusable, testable component, a class is the right abstraction.
